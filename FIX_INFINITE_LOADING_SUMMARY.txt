A) PŘÍČINA NEKONEČNÉHO NAČÍTÁNÍ

1. Chybějící retry limit v loadArticlesOnly/loadVideosOnly
   - Soubor: filtr/assets/app.js, řádky 1564-1648
   - Problém: Pokud fetch selhal, mohl se opakovat nekonečně
   - Oprava: Přidána retry policy s max 3 pokusy a exponenciálním backoffem

2. Chybějící loading timeout
   - Soubor: filtr/assets/app.js, řádek 1803-1809
   - Problém: UI zůstalo v loading stavu, pokud se data nenačetla
   - Oprava: Přidán timeout 8s s fallback UI

3. SW cache vrací HTML místo JSON
   - Soubor: filtr/sw.js, řádky 120-167
   - Problém: SW mohl cacheovat HTML error stránku jako JSON
   - Oprava: Validace, že cached response je skutečně JSON (začíná { nebo [)

4. BASE detekce pro github.io
   - Soubory: filtr/assets/app.js řádek 4-12, filtr/assets/app-crash-shield.js řádek 337-344, filtr/sw.js řádek 34-47
   - Problém: BASE se detekoval z pathname, ale pro github.io musí být "/filtr/"
   - Oprava: Explicitní kontrola hostname.endsWith("github.io") → BASE = "/filtr/"

5. Workflow update-articles.yml padalo
   - Soubor: .github/workflows/update-articles.yml
   - Problém: Chyběla validace JSON, pip upgrade, robustní error handling
   - Oprava: Přidána validace JSON, pip upgrade, fallback na merge při rebase failu

PO:
.catch(async () => {
  const cached = await caches.match(event.request);
  if (cached) {
    const text = await cached.clone().text();
    if (text.trim().startsWith("{") || text.trim().startsWith("[")) {
      return cached;
    }
  }
  return new Response(JSON.stringify({ error: "Network failed and no cache" }), ...);
})

D) SHRNUTÍ OPRAVY WORKFLOW

Příčina pádu update-articles.yml:
- Chyběla validace JSON souborů (mohly být HTML)
- Chybělo pip upgrade (staré verze pip)
- Git rebase mohl failnout bez fallbacku

Oprava:
- Přidána validace JSON před commitem (kontrola existence + validita + ne HTML)
- Pip upgrade před instalací závislostí
- Git pull s fallbackem na merge pokud rebase failne
- OUTPUT_DIR: filtr/data zajišťuje, že build_articles.py generuje na správné místo
